# Verifying porchlight releases

Signed release verification instructions (PORCH-002 ac-5). GitHub Releases are
the signed supply-chain anchor of record for porchlight (Distribution and
Licensing, Porchlight Server TS 2); npm is the install surface (Brian,
Oct 13, 2026 — npm only). Every release's artifacts are checksummed by
`SHA256SUMS` and that file is signed with a Sigstore keyless signature
(`SHA256SUMS.bundle`) whose identity is pinned to the porchlight deploy
workflow in this repository. No verification key lives in the repo — the
trust anchor is the Sigstore OIDC identity (`https://token.actions.githubusercontent.com`
issuer) plus the Rekor transparency log entry bundled in the signature.

## Prerequisites

- Node.js >= 24 (porchlight engines floor)
- [cosign](https://docs.sigstore.dev/cosign/overview/) >= v2 (macOS: `brew install cosign`)

## One-shot verification (recommended)

Clone the repo at the tag being verified and run the verification script
against that release:

```bash
git clone --branch v0.1.0 --depth 1 https://github.com/bjoshuanoah/porchlight.git
cd porchlight
node scripts/release/verify-release.mjs --tag v0.1.0
```

Expected output ends with `✓ VERIFIED — release artifact set is intact and
signed.` and prints the exact identity regexp and issuer the signature was
checked against.

## What the script checks

1. `SHA256SUMS` exists and is well-formed.
2. Every other release asset is covered by a `SHA256SUMS` entry (no unlisted artifacts).
3. Every artifact's sha256 matches its `SHA256SUMS` entry (tamper detection).
4. `SHA256SUMS.bundle` verifies via `cosign verify-blob` against:
   - OIDC issuer: `https://token.actions.githubusercontent.com`
   - identity regexp: `^https://github\.com/bjoshuanoah/porchlight/\.github/workflows/deploy\.yml@`
   (the signature was minted by the deploy workflow of this repository and
   recorded in the transparency log — not by a local or unknown actor).

## Manual verification (without the script)

```bash
# download the assets (npm tarballs + SHA256SUMS + SHA256SUMS.bundle) into one dir
# ...all asset URLs: https://github.com/bjoshuanoah/porchlight/releases/download/v0.1.0/<asset>
curl -LO https://github.com/bjoshuanoah/porchlight/releases/download/v0.1.0/SHA256SUMS
curl -LO https://github.com/bjoshuanoah/porchlight/releases/download/v0.1.0/SHA256SUMS.bundle
# ...and the tarballs listed in SHA256SUMS (checksum + signature integrity)
shasum -a 256 -c SHA256SUMS
cosign verify-blob SHA256SUMS --bundle SHA256SUMS.bundle \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  --certificate-identity-regexp '^https://github\.com/bjoshuanoah/porchlight/\.github/workflows/deploy\.yml@'
```

## Behavior on missing/invalid signatures

Verification fails **loudly** — non-zero exit code and an explicit
`✗ VERIFY FAILED:` report — when artifacts are unsigned, checksums mismatch,
an asset is uncovered, or the cosign identity does not match the pinned
regexp. An unsigned artifact from any other source never passes.

## Verifying npm provenance (registry side)

Every published package also carries an SLSA build provenance attestation
generated by the deploy workflow's GitHub Actions OIDC token
(`.npmrc` `publish-provenance=true`, publish step runs with
`--provenance`). Check it against a published version:

```bash
npm audit signatures @porchlight/shared@0.1.0
```
